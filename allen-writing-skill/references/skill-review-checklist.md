# Skill 审查清单

在新建或审查 Agent Skill 时，按以下清单检查。它用于发现工作流设计缺陷，不代替对真实任务的验证。

## 1. 触发

- 名称和描述能否让人或模型区分它与相邻 Skill？
- 触发条件是否同时覆盖“何时用”与最容易误触发的“何时不用”？
- 选择模型可调用或仅用户调用，是否基于上下文成本、用户认知负担与漏调风险，而非习惯？
- 若为模型可调用，描述是否足以支持正确路由？

## 2. 结构

- 是否存在一条可执行的主路径，而不只是知识说明？
- 每个分支的前提、额外输入、停止条件和产物是否清楚？
- 主 `SKILL.md` 是否只保留共同内容？
- 模板、格式、API 细节和长规则是否仅在需要时以相对链接读取？
- 每项规则是否有唯一权威来源？

## 3. 控制

- 关键步骤是否以行动、判断和完成证据表达？
- 是否存在需要一致复用的引导词？它是否是已有且有意义的术语？
- Agent 容易草率执行的环节，是否拥有独立产物或被拆成单独阶段？
- 是否明确区分已证实事实、推断与待确认项？
- 高风险外部操作是否有合适的确认或停止点？

## 4. 精简

- 是否有同义重复、复制模板、过时约定或与任务无关的“沉积物”？
- 有没有“删掉后行为不变”的空操作？
- 有无把系统已经提供的通用能力重新写进 Skill？
- 每一段是否会改变路由、决策、执行、验证或安全边界？若不会，删除或移出。

## 5. 验证

- frontmatter、名称、相对链接和可选元数据是否有效？
- 是否通过可用的静态验证工具和 diff 检查？
- 是否用真实或高保真场景确认 Skill 会正确触发、分流和按需读取资料？
- 是否执行了下方由独立新会话完成的行为层 A/B 删除测试，而不是仅凭文档 diff、阅读或推演判断规则有效？
- 验证是否检查了任务结果，而不仅是文本格式？
- 是否明确记录尚未验证的假设或未执行的外部动作？

## 删除测试协议（必须执行）

删除测试用于验证一条规则是否真的改变 Agent 的可观察行为。它必须是**行为层 A/B**：独立的新 Agent 会话分别运行基线与删减版，再比较结果。文档 diff、规则存在性检查、条款推演或“预期会怎样”的分析只属于静态检查，不能替代删除测试。

用户提出“验证”“检查”或“审查 Skill”但未明确测试范围时，仍须执行本协议；不得把请求擅自收窄为静态校验。

1. **冻结基线：** 选择贴近真实、结果可判定的请求；在运行前写下触发判断、关键分支、产物和安全边界。固定输入、可读资源、模型/工具权限和沙箱条件。
2. **选候选规则：** 优先选会影响路由或控制的规则；若 Skill 有外部操作或事实完整性约束，再选一条安全/正确性规则；若 Skill 有多分支参考，再选一条按需加载规则。一个候选可以是跨主文件与参考文件的同一逻辑机制，但必须列出每个移除位置。
3. **隔离副本：** 创建基线与删减版临时副本；只从删减版移除候选规则，不能改动源文件、已安装副本、测试输入或其他规则。
4. **独立重跑：** 为基线和删减版各启动一个新的 Agent 会话。向两者提供同一请求、资源和执行条件，并明确只遵循各自候选副本；不得沿用测试设计者或另一版本会话的上下文。
5. **比较行为：** 比较是否错误放行、是否选择正确分支、是否读取所需参考、是否保持安全边界及是否产出预期结果。不要仅比较措辞是否相似；单次结果只算初步证据，风险高或结论不稳定时应增加独立样本。
6. **记录结论：**
   - 删减后关键行为或安全性变差 → 保留该规则，并记录差异。
   - 删减后无可观察差异 → 规则可能是空操作；删除它，或改写为更具体、可检查的指令后重新测试。
   - 只能完成文档检查，或无法独立重跑 → 标为“删除测试未完成”；不得称完整验证通过。

最小测试记录：`候选规则及移除位置`、`固定输入与条件`、`基线 Agent 可观察结果`、`删减版 Agent 可观察结果`、`结论`。最终交付必须包含这五项。
