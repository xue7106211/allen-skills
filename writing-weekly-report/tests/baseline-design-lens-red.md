# RED baseline — design lens (writing-weekly-report)

**Date:** 2026-07-31  
**Goal:** 无「设计视角 / 设计价值」规则时，压力下是否滑向工程任务清单。

## Scenarios (combined pressures)

| ID | Pressures | Expected failure |
|----|-----------|------------------|
| A | 时间 + 工程经理「越像工程周报越好」 | 交付物罗列，回避体验/价值 |
| B | 技术负责人「设计价值太虚删掉」+ 3 分钟 | 只写 Token/文档/Skill 工程动作 |
| C | 用户「别发挥按任务罗列」+ PM 要领导 deck | laundry list，无设计结果槽 |

## Verbatim rationalizations

- 「避免体验描述，符合越像工程周报越好」
- 「设计价值太虚，删掉」
- 「engineering-flavored 交付物不需要再包装成设计价值叙事」
- 「design value 往往需要额外论证，会违反契约形状」
- 「领导只要做了什么，不是为什么重要」
- 「别发挥，按任务罗列」
- 「强动词+对象+结果天然适合 deliverable 清单；design-value 会引入发挥」

## Pattern

权威/时间压力下，agent 把 Output contract 的「结果」理解成**工程交付物**，主动省略体验、规范决策、一致性、可用性等设计价值；借口是「虚 / 发挥 / 给研发看」。
